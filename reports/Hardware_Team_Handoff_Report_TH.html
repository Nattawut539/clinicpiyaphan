1. ขอบเขตและภาพรวมการทำงาน

1.1 เป้าหมาย

ให้อุปกรณ์รับรองตัวตนผู้ป่วยคิวออนไลน์ด้วย OTP หรือสร้างคิว Walk-in จากผลวัด ส่งน้ำหนักและส่วนสูงให้ Backend บันทึก แล้วรับงานพิมพ์ที่มีค่า BMI ซึ่ง Backend เป็นผู้คำนวณ

2. MQTT Contract ที่ต้องใช้ตรงกัน

ทิศทางTopic suffixหน้าที่QoS / Retain
ESP32 → Backend/otp-verifyตรวจ OTP และขอ Measurement SessionQoS 1 / false
Backend → ESP32/otp-resultตอบ Session, Queue A, expires_at หรือ errorQoS 1 / false
ESP32 → Backend/measurementsส่ง Weight / Height / measured_atQoS 1 / false
Backend → ESP32/measurement-ackยืนยัน accepted / duplicate / rejectedQoS 1 / false
Backend → ESP32/printส่ง Queue, Weight, Height, BMI และ Print Job IDQoS 1 / false
ESP32 → Backend/print-ackตอบ printed หรือ failed + error_codeQoS 1 / false

Topic เต็ม: clinic/v1/devices/{deviceId}/{action}

Production transport: MQTT 3.1.1 หรือ MQTT 5 ผ่าน mqtts:// port 8883, UTF-8 JSON, payload ไม่เกิน 16 KB

2.1 Online OTP request

{ "schema_version": "1.0", "request_id": "REQ-A-000001", "device_id": "SCALE-001", "otp": "123456" }

2.2 Measurement payload

{ "schema_version": "1.0", "message_id": "MSG-A-000001", "device_id": "SCALE-001", "mode": "online", "measurement_session_id": "<UUID จาก otp-result>", "measured_at": "2026-09-16T06:50:00.000Z", "weight": 60.0, "height": 170.0 }

2.3 Print acknowledgement

{ "print_job_id": "PRINT-<id จาก Backend>", "device_id": "SCALE-001", "status": "printed" }
ห้าม: ใช้ Retain กับ Measurement, ใช้ device_id ไม่ตรงกับ Topic, เปลี่ยน payload แต่ใช้ message_id เดิม หรือพิมพ์ print_job_id เดิมซ้ำ

4. ข้อกำหนดที่ทีม Firmware ต้องรองรับ

ลำดับข้อกำหนดเกณฑ์ที่ถือว่าผ่าน
F-01สร้าง request_id/message_id ใหม่และไม่ซ้ำRetry ใช้ ID เดิมเฉพาะ payload เดิม; งานใหม่ต้องใช้ ID ใหม่
F-02ตรวจ Correlation ของ OTPรับเฉพาะ otp-result ที่ request_id ตรงกับคำขอปัจจุบัน
F-03ตรวจ Session และ expiryไม่เริ่ม/ไม่ส่ง Measurement เมื่อ Session หมดอายุ
F-04เวลา UTC จาก NTPส่ง measured_at เป็น ISO-8601 UTC ลงท้าย Z และไม่อยู่ในอนาคตผิดปกติ
F-05เก็บ Pending ก่อน Publishตัดไฟหรือหลุดเครือข่ายแล้วกลับมาส่ง payload/message_id เดิมได้
F-06รอ Measurement ACKaccepted/duplicate จึงลบ Pending; rejected ต้องแสดง error และหยุด retry ตามประเภท
F-07Reconnect และ resubscribeกลับมา online และ subscribe ทุก topic ที่จำเป็นด้วย QoS 1 โดยอัตโนมัติ
F-08ตรวจ Print Job schemaมี print_job_id, queue_number, weight, height, bmi, measured_at ครบ
F-09Deduplicate การพิมพ์จำ print_job_id ในหน่วยความจำถาวรและไม่พิมพ์ ID เดิมซ้ำแม้ MQTT ส่งซ้ำ
F-10ตอบ Print ACKprinted เมื่อสำเร็จ; failed พร้อม error_code ที่สม่ำเสมอเมื่อไม่สำเร็จ
F-11ห้ามคำนวณ BMI ใหม่ใช้ค่า BMI จาก Print Job เป็นค่าที่พิมพ์และแสดง
F-12รองรับ Payload จำกัดUTF-8 JSON ไม่เกิน 16 KB และไม่ใช้ Retain

4.1 Error code ที่ต้องแสดงหรือบันทึก

INVALID_OTP, OTP_NOT_FOUND, OTP_EXPIRED, OTP_USED, OTP_NOT_ACTIVE_YET, INVALID_SESSION, DEVICE_MISMATCH, WEIGHT_OUT_OF_RANGE, HEIGHT_OUT_OF_RANGE, RETAIN_NOT_ALLOWED, RATE_LIMITED, MESSAGE_ID_CONFLICT, INTERNAL_ERROR

4.2 Print error code ขั้นต่ำ

  • PRINTER_NOT_CONNECTED — ไม่มีหรือเชื่อมต่อเครื่องพิมพ์ไม่ได้ (Backend ไม่ retry)
  • PAPER_OUT — กระดาษหมด (Backend อาจ retry ตาม backoff)
  • UNSUPPORTED_SCHEMA — ไม่รองรับ schema (Backend ไม่ retry)
  • INVALID_PRINT_JOB / INVALID_PRINT_DATA — ข้อมูลงานพิมพ์ไม่ถูกต้อง (Backend ไม่ retry)

5.1 หลักฐานที่ต้องส่งกลับ

  • Serial log ที่มี timestamp, topic, request_id/message_id/print_job_id และผลลัพธ์ โดยไม่เปิดเผย OTP/Password
  • ภาพหน้าจอ LCD และใบพิมพ์ที่เห็น Queue, Weight, Height, BMI ตรงกับ Backend
  • ผล Calibration พร้อมอุปกรณ์มาตรฐานและค่าความคลาดเคลื่อน
  • วิดีโอหรือ log ของกรณีตัด Wi-Fi/ตัดไฟ/reconnect และ duplicate handling
  • ตาราง Firmware version, board, build environment, RAM/Flash usage และ commit hash
ห้ามทดสอบ destructive case กับข้อมูลผู้ป่วยจริง: ใช้นัดหมายและคิวทดสอบที่กำหนดร่วมกันเท่านั้น และลบข้อมูลทดสอบตามกระบวนการของทีม Software

6.1 Production security checklist

  • ใช้ mqtts://, ตรวจ CA certificate และเปิด reject unauthorized
  • Username/Password และ Client ID ต้องไม่ฝังใน source repository หรือ log
  • Device publish ได้เฉพาะ otp-verify, measurements, print-ack ของตน
  • Device subscribe ได้เฉพาะ otp-result, measurement-ack, print ของตน
  • กำหนดวิธี revoke/rotate credential เมื่ออุปกรณ์สูญหายหรือถูกเปลี่ยน
