# ผลทดสอบการจองคิวและอีเมลเตือนนัด

ทดสอบผ่าน HTTP API จริงและ PostgreSQL ที่สร้างแยกชั่วคราวจาก schema ของโปรเจกต์ ใช้ฟังก์ชัน `sendClinicMail` ตัวเดียวกับอีเมลรับคำขอและอีเมลอนุมัติคิว โดยแทนเฉพาะการเชื่อมต่อ SMTP ด้วย Nodemailer stream transport เพื่อสร้างอีเมลโดยไม่ส่งหาผู้ใช้จริง ฐานข้อมูลทดสอบถูกลบหลังจบงาน

## พฤติกรรมที่เพิ่ม

- คิวต้องได้รับอนุมัติ (`approved`) และเป็นคิว A ที่รอรับบริการ (`waiting`)
- แจ้งเมื่อวันนัดเป็นวันพรุ่งนี้ตาม Asia/Bangkok ไม่ใช่การนับย้อนหลัง 24 ชั่วโมงพอดี
- ใช้งานแจ้งเตือนเดิม: เริ่มตรวจหลัง Backend เปิดประมาณ 10 วินาที แล้วตรวจทุก 15 นาที รวมถึงคิวที่เพิ่งได้รับอนุมัติระหว่างวัน
- อีเมลมีข้อความ “คุณมีนัดพรุ่งนี้” พร้อมวัน เวลา และหมายเลขคิว
- เก็บประวัติแยกตามนัดและวันที่ใน `user_notifications` ป้องกันการส่งซ้ำจากการรันปกติและหลาย worker พร้อมกัน
- ตรวจสถานะและวันนัดอีกครั้งก่อนส่ง คิวที่ยกเลิกหรือเลื่อนวันจะไม่ส่งเตือนวันที่เดิม
- ส่งล้มเหลวจะลองใหม่ในรอบถัดไปตราบใดที่ยังเป็นวันก่อนนัด
- ใช้ schema เดิม ไม่ต้องเพิ่ม migration สำหรับฟีเจอร์นี้

## ผลทดสอบ

ผ่าน 10 กรณี (Node test runner แสดง 11 tests เมื่อนับชุดทดสอบหลัก)

1. ผู้ใช้จองผ่าน API ได้สถานะรออนุมัติและอีเมลรับคำขอ แต่ยังไม่ส่งเตือน
2. ผู้ใช้อนุมัติเองไม่ได้; Admin อนุมัติได้ พร้อมสร้างคิว A003 และอีเมลยืนยัน
3. ไม่ส่งล่วงหน้าสองวัน; เริ่มเข้าเงื่อนไขเมื่อถึงเที่ยงคืนไทย และตรวจวัน เวลา คิว ภาษาไทย การ escape HTML และ MIME อีเมล
4. รันซ้ำไม่ส่งอีเมลเตือนซ้ำ
5. ไม่ส่งสำหรับนัด pending/cancelled/rejected/completed/no_show หรือคิวที่ยกเลิก
6. ไม่ส่งข้อความ “พรุ่งนี้” ในวันนัดหรือหลังวันนัด
7. SMTP ล้มเหลวหรือปฏิเสธผู้รับไม่ถูกนับว่าส่งแล้ว และลองใหม่ได้
8. Worker สามชุดทำงานพร้อมกันส่งเพียงครั้งเดียว
9. ไม่มีอีเมลจะข้าม และใช้อีเมลในข้อมูลส่วนตัวเป็นค่าทดแทนได้
10. เลื่อนนัดแล้วไม่ส่งตามวันเดิม แต่ส่งก่อนวันนัดใหม่ได้

## รันทดสอบซ้ำ (PowerShell)

ต้องมี PostgreSQL ในเครื่องและ `backend/.env` ที่บัญชีฐานข้อมูลมีสิทธิ์สร้างฐานข้อมูลทดสอบ คำสั่งยอมรับเฉพาะ localhost และใช้ชื่อฐานข้อมูลชั่วคราวที่สร้างใหม่เอง

```powershell
$env:REMINDER_TEST_LOCAL = 'true'
npm --prefix backend run test:appointment-reminders
Remove-Item Env:REMINDER_TEST_LOCAL
```

## ขอบเขตผลทดสอบและการใช้งาน

ผู้ใช้ยืนยันว่าอีเมลรับคำขอและอีเมลที่ Admin อนุมัติคิวส่งถึงผู้ใช้งานจริงแล้ว ฟีเจอร์เตือนนัดใช้ `sendClinicMail` และการตั้งค่า SMTP ชุดเดียวกัน จึงอ้างอิงผลทดสอบระบบส่งอีเมลเดิมร่วมกับผลทดสอบเงื่อนไขเตือนนัดในชุดนี้ โดยรอบนี้ไม่ได้ส่งอีเมลเตือนนัดไปยังกล่องจดหมายจริง

เมื่อนำโค้ดไปใช้งานให้รีสตาร์ต Backend และใช้ค่า SMTP เดิม (`DISABLE_EMAIL` ต้องไม่เป็น `true`) โดย Backend ต้องทำงานในวันก่อนนัด หากเซิร์ฟเวอร์หยุดทั้งวัน ระบบจะไม่ย้อนส่งข้อความ “พรุ่งนี้” ในวันนัด

SMTP และฐานข้อมูลไม่สามารถ commit ร่วมกันได้: หาก SMTP รับอีเมลแล้วแต่โปรเซสหยุดก่อนบันทึกประวัติ อาจส่งซ้ำเมื่อกู้คืนได้ การทดสอบป้องกันซ้ำครอบคลุมการรันปกติและพร้อมกัน ไม่ใช่การรับประกัน exactly-once เมื่อระบบล่ม
